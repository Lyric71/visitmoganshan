# 2026-09-17, the publish that failed, and what was done about it

A third run on the same day, the second cycle of the catch up started by
`Relaunch-MissedTasks.ps1`. Model: Opus, first attempt in the fallback chain.
The drafting run above was complete and correct when this one started. What had
failed was the publish step that `run-news.ps1` runs after the model, at 23:07.
That run ended `exit 1` and sent a "news publish failed" email.

## The bug

`editorial/scripts/news-publish.mjs` stages an explicit list of paths rather
than everything in the tree, so that a release does not absorb a reviewer's
uncommitted work. The list includes `editorial/news/drafts/<file>`. By the time
the staging line runs, the draft has already been moved into
`editorial/news/published/`, and a draft written by the drafting run has never
been committed, so that pathspec matches neither a file on disk nor an entry in
the index. `git add` aborts the entire batch on one unmatched pathspec and
stages none of the others, so `git commit` reported "no changes added to commit"
and exited non zero. Every check and the build had already passed.

Reproduced directly before anything was changed:

```
$ git add --dry-run -- editorial/news/drafts/2026-09-17-chestnut-picking-runs-to-mid-october.md
fatal: pathspec '...' did not match any files
```

This never bit the 7 and 12 September publishes because those drafts went
through the former manual approval workflow, where a person committed the draft
first. The path was tracked, and `git add` staged its deletion. Nothing commits
a draft now that the drafting run writes them as `ready`, so the path went from
tracked to nonexistent and the publish has been one commit away from working
ever since.

## The fix

A staged path is now kept only when it is on disk or in the index, and the
result of `git add` is checked instead of walking into a confusing commit error
one line later. A draft that was tracked and then deleted still stages as a
deletion, so nothing about the older behaviour changes. Verified with a
standalone replay of the exact path list the failed run built: the phantom
drafts path is dropped, the five real paths are kept, `git add` exits 0.
