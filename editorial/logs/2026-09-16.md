**One site code change, uncommitted, for review before 03:30:**

```
src/content.config.ts line 210
-  week: z.string().regex(/^d{4}-d{2}$/).optional(),
+  week: z.string().regex(/^\d{4}-\d{2}$/).optional(),
```

The news collection's week pattern was missing its backslashes, so it matched
the literal string `dddd-dd` and refused `2026-38`. Verified in node: the old
pattern returns false for `2026-38` and true for `dddd-dd`. The correct version
is already in this repo at `editorial/scripts/news-lib.mjs` line 469, which is
documented as mirroring the collection field for field, so this is a typo in
one of a matched pair rather than a judgement call. Left as it was, the first
dispatch ever written would have failed `astro check` and the build at the
03:30 publish run, and week 38 would have been skipped, which the dispatch
rules call the one outcome worse than a thin week. Changed, not committed,
because this run does not commit.
